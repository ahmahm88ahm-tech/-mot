## 1. نظرة عامة على لوحة التحكم

### 1.1 الغرض

لوحة التحكم في MOTANAQIL هي أداة إدارية متكاملة تُمكّن الفرق الإدارية من:

- إدارة الطلبات بشكل فعال
- مراقبة أداء النظام
- إدارة الموظفين والخدمات
- تحليل البيانات واتخاذ القرارات
- إدارة المحتوى بسهولة

### 1.2 المستخدمون المستهدفون

- **Super Admin**: المسؤول النهائي عن النظام
- **Admin**: مديرو النظام
- **Manager**: مديرو الفرق
- **Employee**: الموظفون (لإدارة طلباتهم)

### 1.3 الميزات الرئيسية

✅ **واجهة سهلة الاستخدام**  
✅ **التحليلات والبيانات**  
✅ **إدارة الطلبات المتكاملة**  
✅ **الإشعارات في الوقت الفعلي**  
✅ **الدعم متعدد القنوات**  
✅ **التوثيق الشامل**  
✅ **التصميم المتجاوب**  
✅ **الوصول من أي جهاز**

### 2.2 التصميم المعماري

#### 2.2.1 مبدأ 100% API-first

- جميع الميزات مبنية على API
- واجهة المستخدم هي مجرد استهلاك لـ API
- يسمح بالوصول من أي جهاز
- يسمح بالتطوير المستقل

#### 2.2.2 Component-Based Architecture

- مكونات قابلة لإعادة الاستخدام
- مكونات مُعَدَّة مسبقاً
- مكونات مُخصصة للمشروع
- توثيق مفصل للمكونات

#### 2.2.3 مبدأ الـ Single Source of Truth

- جميع البيانات من مصدر واحد (الـ API)
- تجنب تكرار البيانات
- تجنب التناقض في البيانات
- تجنب الاعتماد على حالة الواجهة

### 5.3 الميزات الرئيسية

#### 5.3.1 فلترة متقدمة

- **الحالة:**.created, .confirmed, .assigned, .in_progress, .completed, .cancelled
- **الأولوية:** low, normal, high, urgent
- **المدينة:** الرياض، جدة، الدمام، ...
- **الفترة الزمنية:** اليوم، الأسبوع، الشهر، السنة
- **البحث النصي:** رقم الطلب، اسم العميل، رقم الهاتف

#### 5.3.2 عرض البيانات

- **الجدول:** ترتيب، تصفية، تحميل البيانات
- **العرض البصري:** خريطة التفاعلية
- **العرض المخصص:** وفقاً لدور المستخدم

#### 5.3.3 إدارة الطلبات

- **الاختيار الجماعي:** تعيين موظف، تغيير الحالة
- **التفاصيل الفردية:** عرض تفاصيل الطلب
- **المراسلات:** محادثة مع العميل والموظف
- **التقييم:** تقييم الخدمة
- **الإلغاء:** إلغاء الطلب مع سبب

#### 5.3.4 تقارير مخصصة

- **الطلبات حسب الخدمة**
- **الطلبات حسب المدينة**
- **الطلبات حسب الموظف**
- **الطلبات حسب الوقت**
