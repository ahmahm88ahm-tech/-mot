## 1. One-to-Many Relations

### 1.1 Region → Cities
```
Region (1) ──────< Cities (N)
```
- **الوصف:** المنطقة تحتوي على عدة مدن
- **Foreign Key:** `cities.region_id`
- **Cascade:** لا حذف تلقائي
- **مثال:** منطقة الرياض → الرياض، الخرج، الدرعية

### 1.2 City → Districts
```
City (1) ──────< Districts (N)
```
- **الوصف:** المدينة تحتوي على عدة أحياء
- **Foreign Key:** `districts.city_id`
- **Cascade:** حذف تلقائي للأحياء عند حذف المدينة
- **مثال:** الرياض → النرجس، الياسمين، الملقا

### 1.3 City → Branches
```

```

## 2. Many-to-Many Relations

### 2.1 User ↔ Roles
```
User (N) ──────< UserRoles >────── (N) Roles
```
- **الوصف:** المستخدم له عدة أدوار، والدور له عدة مستخدمين
- **Junction Table:** `user_roles`
- **Foreign Keys:** `user_roles.user_id`, `user_roles.role_id`
- **Cascade:** حذف تلقائي عند حذف المستخدم أو الدور
- **مثال:** أحمد → [Admin, Manager]

### 2.2 Role ↔ Permissions
```
Role (N) ──────< RolePermissions >────── (N) Permissions
```
- **الوصف:** الدور له عدة صلاحيات، والصلاحية في عدة أدوار
- **Junction Table:** `role_permissions`
- **Foreign Keys:** `role_permissions.role_id`, `role_permissions.permission_id`
- **Cascade:** حذف تلقائي عند حذف الدور أو الصلاحية
- **مثال:** Admin → [create_order, delete_order, manage_users]

## 3. Self-Referencing Relations

### 3.1 MenuItems → MenuItems (Parent-Child)
```
MenuItem (1) ──────< MenuItems (N)
```
- **الوصف:** عنصر القائمة له عناصر فرعية
- **Foreign Key:** `menu_items.parent_id`
- **Cascade:** حذف تلقائي للعناصر الفرعية عند حذف الأب
- **مثال:** الخدمات → [نقل عفش، فك وتركيب، تغليف]

## 6. Cascade Rules

### 6.1 حذف تلقائي (CASCADE)
- حذف المدينة → حذف الأحياء
- حذف الطلب → حذف الصور، سجل الحالات، التقييمات
- حذف المستخدم → حذف الإشعارات
- حذف القائمة → حذف العناصر
- حذف السلايدر → حذف العناصر
- حذف الموظف → حذف المواقع

### 6.2 لا حذف تلقائي (NO ACTION)
- حذف المنطقة → لا حذف المدن (يجب نقل المدن أولاً)
- حذف المستخدم → لا حذف الطلبات (تبقى الطلبات محفوظة)
- حذف الخدمة → لا حذف الطلبات (تبقى الطلبات محفوظة)
- حذف الفرع → لا حذف الطلبات (تبقى الطلبات محفوظة)

## 7. Integrity Constraints

### 7.1 Foreign Key Constraints
- جميع العلاقات يجب أن تكون صحيحة
- لا يمكن إنشاء طلب بدون عميل صالح
- لا يمكن إنشاء طلب بدون خدمة صالحة
- لا يمكن تعيين موظف غير موجود

### 7.2 Unique Constraints
- `users.email` فريد
- `users.phone` فريد
- `users.national_id` فريد
- `orders.order_number` فريد
- `services.slug` فريد
- `cities.slug` فريد
- `districts.slug` فريد (ضمن المدينة)
- `settings.key` فريد
- `pages.slug` فريد
- `blogs.slug` فريد

### 7.3 Check Constraints
- `orders.status` يجب أن يكون من القيم المسموحة
- `orders.priority` يجب أن يكون من القيم المسموحة
- `orders.payment_status` يجب أن يكون من القيم المسموحة
- `reviews.rating` بين 1 و 5
- `services.price_unit` يجب أن يكون من القيم المسموحة
- `notifications.channel` يجب أن يكون من القيم المسموحة
