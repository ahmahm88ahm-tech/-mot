# ADR-0007 — Replit Build Pragmatics (Minimum Buildable Product)

**الحالة:** مقبول  
**التاريخ:** 2026-07-24  
**يرتبط بـ:** PM-003

---

## السياق

البناء على Replit له قيود عملية: بيئة Node.js واحدة لكل Repl، وpnpm/turbo قد يكونان هشّين، والتعقيد الزائد يرفع احتمال فشل البناء الأول.

---

## القرار

### 1. لا monorepo workspaces معقّدة

كل تطبيق (`apps/api`، `apps/web`، `apps/admin`) مكتفٍ بذاته مع `package.json` خاص به وتنصيب `npm install` منفصل. يتجنب هشاشة pnpm workspaces/turbo على Replit.

**الثمن:** تكرار بعض الإعدادات.  
**الكسب:** بناء أول ناجح مضمون.

### 2. DTOs مسطّحة

لا كائنات متداخلة في DTOs الـ API — تفادي اعتماديات `class-transformer` الهشة.

### 3. `prisma db push` بدل `migrate`

على Replit، `prisma db push` أسرع وأقل احتمالاً للفشل من `migrate dev` في البيئات المؤقتة.

### 4. لا Tailwind/Zustand في MBP

CSS variables مباشرة + `useState` محلي. يُضافان في الحزمة اللاحقة.

---

## العواقب

- البناء الأول يعمل بأمر واحد لكل تطبيق.
- إضافة monorepo tools أو Tailwind تأتي في الحزمة الثانية فوق أساس مُثبَت.
