# PM-008 — إصلاح بنية الـ Workspace وتجهيز apps/web للتشغيل

**التاريخ:** 2026-07-25  
**الحالة:** مدمج في المصدر  
**القرار:** سدّ فجوات الربط الأربع بخمسة ملفات دون المساس بالكود الحيّ

## التشخيص

كانت الكود المصدري لـ `apps/web` و`apps/api` موجوداً كاملاً (287 ملفاً)، لكن أربع فجوات ربط تمنع التشغيل:

| الفجوة | السبب |
|---|---|
| `apps/web/package.json` غير موجود | الواجهة بلا تعريف حزمة — لا تُثبَّت ولا تُشغَّل |
| `apps/web` غير مدرج في الـ workspace | `pnpm-workspace.yaml` لا يرى `apps/web` |
| `apps/api` غير مدرج في الـ workspace | نفس السبب |
| الجذر بلا سكربتات احتياطية | لا طريقة لتشغيل كل تطبيق بشكل مستقل عند الحاجة |

## الملفات الإصلاحية الخمسة

### 1. `apps/web/package.json` — جديد

تعريف حزمة `@motanaqil/web` بـ Next.js 14 و React 18. يحترم متغير `PORT` الذي يعيّنه Replit تلقائياً.

### 2. `apps/web/tsconfig.json` — جديد

إعداد TypeScript لـ Next.js مع مسار `@/*` لاستيراد الملفات من `src/`.

### 3. `apps/web/next.config.js` — جديد

إعداد Next.js الأساسي مع `reactStrictMode`.

### 4. `pnpm-workspace.yaml` — تحديث

إضافة `apps/*` إلى قائمة packages مع الحفاظ على كل المحتوى الحالي (catalog، overrides، minimumReleaseAge).

### 5. `package.json` الجذر — تحديث

إضافة سكربتات احتياطية باستخدام `npm --prefix` تُشغّل كل تطبيق مستقلاً دون الاعتماد على pnpm workspaces. قرار ADR-0008: كل تطبيق مكتفٍ بذاته.

## الاستراتيجية

لم يُمسَّ `apps/api/package.json` ولا أي كود حيّ. التعديلات فجوات ربط فقط لا تعديلات منطقية.

## التشغيل

```bash
# تشغيل الواجهة
cd apps/web && npm install && npm run dev

# أو من الجذر
npm run install:web && npm run dev:web
```

متغير البيئة المطلوب:

```
NEXT_PUBLIC_API_URL=<رابط api-server>
```
