> **الكود يُكتب للبشر أولاً، وللآلة ثانياً.** أي سطر كود لا يحترم هذه المعايير يُرفض في المراجعة تلقائياً. المعايير هنا ليست "اقتراحات" بل **قواعد قابلة للفرض آلياً** (عبر ESLint, Prettier, TypeScript, husky, CI). ما لا يمكن فرضه آلياً يُفرض عبر Code Review الإلزامي. الهدف: **اتساق كامل** يجعل أي ملف في المشروع يبدو وكأنه كُتب بواسطة شخص واحد، بغضّ النظر عمن كتبه فعلياً.

## 1. فلسفة الكود والمبادئ

### 1.1 المبادئ الحاكمة

| المبدأ | المعنى العملي في MOTANAQIL |
|--------|---------------------------|
| **Clarity > Cleverness** | الكود الواضح البسيط يُفضّل دائماً على الكود "الذكي" المعقّد |
| **SOLID** | كل مبدأ مُطبّق ومُراجع (تفصيل أدناه) |
| **DRY** | لا تكرار؛ المنطق المشترك في `packages/` أو `common/` |
| **KISS** | أبسط حل يعمل؛ لا إفراط في الهندسة |
| **YAGNI** | لا نبني ما لا نحتاجه الآن؛ نؤجّل للمرحلة المناسبة |
| **Single Responsibility** | كل ملف/كلاس/دالة لها غرض واحد واضح |
| **Explicit > Implicit** | السلوك الصريح يُفضّل على السحري/الضمني |
| **Fail Fast** | الأخطاء تُكشف مبكراً، لا تُبتلع |

### 1.2 SOLID بالتطبيق

```typescript
// S — Single Responsibility
// ❌ خاطئ: خدمة تفعل كل شيء
class OrderService {
  create() { /* منطق + إشعار + فاتورة + log */ }
}

// ✅ صحيح: كل مسؤولية في كلاس
class OrderService { constructor(private notifier, private invoicer, private logger) {} }
class OrderNotificationService { /* ... */ }
class OrderInvoiceService { /* ... */ }

// O — Open/Closed: مفتوح للإضافة، مغلق للتعديل
// ✅ نستخدم Strategy pattern لإضافة قنوات إشعار بدون تعديل الكود الأصلي
interface NotificationChannel { send(payload): Promise<void>; }
class EmailChannel implements NotificationChannel { /* ... */ }
class SmsChannel implements NotificationChannel { /* ... */ }

// L — Liskov Substitution: الأنواع الفرعية قابلة للاستبدال
// ✅ أي implementation لـ NotificationChannel يعمل في نفس السياق

// I — Interface Segregation: واجهات صغيرة ومحددة
// ❌ interface GodService { 20 method }
// ✅ interface OrderReader { find() }  interface OrderWriter { create() }

// D — Dependency Inversion: الاعتماد على التجريدات، لا التفاصيل
// ✅ constructor(private repo: OrderRepository)  // interface
// ❌ constructor(private repo: PrismaOrderRepository)  // implementation
```

## 3. TypeScript Standards

### 3.1 القواعد الأساسية

```typescript
// ✅ استخدم type imports للفصل
import type { User, Order } from '@motanaqil/types';
import { OrderService } from './order.service';

// ✅ واجهات (interface) للـ object shapes، type للـ unions/aliases
interface UserProfile { id: string; name: string; }
type OrderStatus = 'created' | 'confirmed' | 'completed';
type Nullable<T> = T | null;

// ✅ readonly للمصفوفات والكائنات غير المعدّلة
function getActiveCities(): readonly City[] { /* ... */ }

// ✅ as const للثوابت الحرفية
const ORDER_STATUSES = ['created', 'confirmed', 'completed'] as const;
type OrderStatus = (typeof ORDER_STATUSES)[number];

// ✅ discriminated unions بدلاً من optional fields غامضة
type Result<T> =
  | { success: true; data: T }
  | { success: false; error: AppError };

// ✅ never للـ exhaustive checks
function handleStatus(status: OrderStatus): string {
  switch (status) {
    case 'created': return 'جديد';
    case 'confirmed': return 'مؤكد';
    case 'completed': return 'مكتمل';
    default:
      const _exhaustive: never = status; // خطأ compile إن أضفنا حالة ونسيناها
      return _exhaustive;
  }
}
```

### 3.2 الممنوعات في TypeScript

```typescript
// ❌ any — ممنوع قطعياً
function process(data: any) { }            // ❌
function process(data: unknown) { }        // ✅ ثم narrow

// ❌ type assertion بدون تحقق
const user = response as User;             // ❌
const user = UserSchema.parse(response);   // ✅ validation

// ❌ non-null assertion بدون ضمان
const name = user.profile!.name;           // ❌
const name = user.profile?.name ?? 'N/A';  // ✅

// ❌ enum رقمي (مشاكل معكوسة)
enum Role { Admin, User }                  // ❌
enum Role { Admin = 'admin', User = 'user' } // ✅ أو const object + union

// ❌ Function keyword — نستخدم arrow/const
function add(a, b) { }                     // ❌ في الكود الحديث
const add = (a: number, b: number): number => a + b; // ✅

// ❌ exports default (نفضّل named للـ refactoring الآمن)
export default class Foo {}                // ❌ (مسموح فقط في next pages/layout)
export class Foo {}                        // ✅
```

## 4. NestJS Standards (Backend)

### 4.1 بنية الـ Module

```typescript
// orders/orders.module.ts
@Module({
  imports: [PrismaModule, NotificationsModule, MapsModule],
  controllers: [OrdersController],
  providers: [
    OrdersService,
    OrdersRepository,
    OrdersValidator,
    OrderStateMachine,
    OrderPriceCalculator,
  ],
  exports: [OrdersService], // نصدّر الخدمة فقط، لا الـ repository
})
export class OrdersModule {}
```

**القواعد:**
- ✅ كل feature في module مستقل (modular monolith).
- ✅ الـ controllers لا تحتوي منطق أعمال (thin controllers).
- ✅ الـ services لا تستورد Prisma مباشرة، بل عبر Repository.
- ✅ نصدر الخدمات فقط، لا الـ repositories أو الـ internals.
- ❌ لا اعتماد دائري بين الـ modules (يفرضه ESLint `import/no-cycle`).

### 4.2 Controller Pattern

```typescript
// orders/orders.controller.ts
@ApiTags('Orders')
@ApiBearerAuth()
@Controller({ path: 'orders', version: '1' })
@UseGuards(JwtAuthGuard, RolesGuard)
export class OrdersController {
  constructor(private readonly ordersService: OrdersService) {}

  @Post()
  @Roles('customer', 'admin')
  @HttpCode(HttpStatus.CREATED)
  @ApiOperation({ summary: 'إنشاء طلب جديد' })
  @ApiCreatedResponse({ type: OrderResponseDto })
  async create(
    @Body() dto: CreateOrderDto,           // validation تلقائي عبر ZodPipe
    @CurrentUser() user: AuthUser,         // custom decorator
    @Req() req: AuthenticatedRequest,
  ): Promise<OrderResponseDto> {
    return this.ordersService.create(dto, user);
    // ❌ لا try/catch هنا — الـ ExceptionFilter يتكفل
    // ❌ لا منطق أعمال — فقط تنسيق
  }

  @Get(':id')
  @Roles('customer', 'admin', 'manager')
  @UseGuards(OwnershipGuard)               // منع IDOR
  @ApiOperation({ summary: 'تفاصيل طلب' })
  async findOne(
    @Param('id', ParseCuidPipe) id: string,
    @CurrentUser() user: AuthUser,
  ): Promise<OrderResponseDto> {
    return this.ordersService.findById(id, user);
  }
}
```

### 4.3 DTOs مع Zod (موحّد مع Frontend)

```typescript
// orders/dto/create-order.dto.ts
import { z } from 'zod';
import { createZodDto } from 'nestjs-zod';
import { CoordinatesSchema } from '@motanaqil/types';

export const CreateOrderSchema = z.object({
  serviceId: z.string().cuid(),

export class CreateOrderDto extends createZodDto(CreateOrderSchema) {}
export type CreateOrderInput = z.infer<typeof CreateOrderSchema>;
```

### 4.4 Service Pattern

```typescript
// orders/orders.service.ts
@Injectable()
export class OrdersService {
  private readonly logger = new Logger(OrdersService.name);

  constructor(
    private readonly ordersRepo: OrdersRepository,
    private readonly stateMachine: OrderStateMachine,
    private readonly priceCalc: OrderPriceCalculator,
    private readonly notifier: NotificationsService,
    private readonly eventBus: EventBusService,
  ) {}

  async create(input: CreateOrderInput, user: AuthUser): Promise<OrderResponseDto> {
    // 1. حساب السعر (Server-side فقط — لا نثق بالـ client)
    const pricing = await this.priceCalc.calculate(input);

    // 2. إنشاء الكيان
    const order = await this.ordersRepo.create({
      ...input,
      customerId: user.id,
      pricing,
      orderNumber: await this.generateOrderNumber(),
    });

    // 3. نشر حدث (بدون await — غير حرج للمسار الرئيسي)
    this.eventBus.emit('order.created', { orderId: order.id, userId: user.id });

    this.logger.log(`Order created: ${order.orderNumber} by user ${user.id}`);

    // 4. إرجاع DTO (لا نرجع entity مباشرة)
    return OrderMapper.toResponse(order);
  }
}
```

**القواعد:**
- ✅ الـ services `@Injectable()` وتعتمد على DI.
- ✅ كل دالة `async` تُرجع Promise صريح النوع.
- ✅ نستخدم `Logger` من NestJS، لا `console`.
- ✅ نرجع DTOs عبر Mapper، لا الـ entities الخام.

## 7. Prisma & Data Access Standards

### 7.1 Repository Pattern

```typescript
// orders/orders.repository.ts
@Injectable()
export class OrdersRepository {
  constructor(private readonly prisma: PrismaService) {}

  async findById(id: string): Promise<Order | null> {
    return this.prisma.order.findUnique({
      where: { id },
      include: { customer: true, service: true, assignedTo: true },
    });
  }

  async findByCustomer(customerId: string, page: Pagination): Promise<Paginated<Order>> {
    const [data, total] = await this.prisma.$transaction([
      this.prisma.order.findMany({
        where: { customerId, deletedAt: null },   // ✅ soft delete filter
        orderBy: { createdAt: 'desc' },
        skip: (page.page - 1) * page.limit,
        take: page.limit,
      }),
      this.prisma.order.count({ where: { customerId, deletedAt: null } }),
    ]);
    return { data, total, page: page.page, limit: page.limit };
  }
}
```

**القواعد:**
- ✅ كل وصول للـ DB عبر Repository، لا `prisma` مباشرة في الـ services.
- ✅ `select` صريح للحقول المطلوبة (لا جلب زائد)، خاصة للـ lists.
- ✅ `include` للعلاقات المطلوبة فقط (تجنب N+1).
- ✅ `$transaction` للعمليات الذرية.
- ✅ `deletedAt: null` في كل query (soft delete).
- ❌ لا `prisma.$queryRaw` إلا للضرورة القصوى، مع parameterization دائماً.

### 8.2 Global Exception Filter

```typescript
// common/filters/all-exceptions.filter.ts
@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  constructor(private readonly logger: AppLogger) {}

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const res = ctx.getResponse<Response>();
    const req = ctx.getRequest<AuthenticatedRequest>();

    const isApp = exception instanceof AppError;
    const isHttp = exception instanceof HttpException;

    const status = isApp ? exception.httpStatus
      : isHttp ? exception.getStatus() : 500;

    const code = isApp ? exception.code
      : isHttp ? 'HTTP_ERROR' : 'INTERNAL_ERROR';

    // ❌ لا نكشف التفاصيل الداخلية للعميل في 500
    const message = status >= 500
      ? 'حدث خطأ غير متوقع. فريقنا يعمل على إصلاحه.'
      : (exception instanceof Error ? exception.message : 'خطأ');

    // تسجيل كامل داخلياً (مع stack للأخطاء البرمجية)
    if (status >= 500) {
      this.logger.fatal('Unhandled exception', {
        error: exception instanceof Error ? exception.stack : exception,
        path: req.path, userId: req.user?.id,
      });
    } else {
      this.logger.warn('Client error', { code, message, path: req.path });
    }

    res.status(status).json({
      success: false,
      error: { code, message, requestId: req.requestId },
    });
  }
}
```

**القواعد:**
- ✅ ارمِ أخطاءً typed (`throw new NotFoundError(...)`)، لا strings.
- ❌ لا `try/catch` لابتلاع الأخطاء بدون إعادة رمي أو تسجيل.
- ✅ الرسائل للعميل بالعربية وآمنة (لا stack traces، لا SQL، لا مسارات).
- ✅ الـ filter الموحّد يلتقط كل شيء ويوحّد الشكل.

```typescript
// common/logger/app-logger.ts
import { LoggerService } from '@nestjs/common';

export class AppLogger implements LoggerService {
  log(msg: string, ctx?: Record<string, unknown>)   { this.write('info', msg, ctx); }
  warn(msg: string, ctx?: Record<string, unknown>)  { this.write('warn', msg, ctx); }
  error(msg: string, ctx?: Record<string, unknown>) { this.write('error', msg, ctx); }
  fatal(msg: string, ctx?: Record<string, unknown>) { this.write('fatal', msg, ctx); }

  private write(level: string, msg: string, ctx?: Record<string, unknown>) {
    const entry = {
      level, msg, ts: new Date().toISOString(),
      service: process.env.SERVICE_NAME, traceId: getTraceId(),
      ...this.redact(ctx),   // ✅ تنقية PII
    };
    process.stdout.write(JSON.stringify(entry) + '\n'); // JSON line للـ SIEM
  }

  private redact(ctx?: Record<string, unknown>) {
    if (!ctx) return {};
    return redactPII(ctx); // يحذف/يقنّع national_id, phone, password, token, card
  }
}
```

**القواعد:**

- ✅ المستويات: `debug` (تطوير فقط)، `info` (أحداث عادية)، `warn` (مشكلة قابلة للاستمرار)، `error` (فشل عملية)، `fatal` (يُسقط العملية).

## 17. Git Workflow التفصيلي

### 17.1 استراتيجية الفروع (Trunk-Based مع حماية)

```
main          ← الإنتاج، محمي، tags فقط (v1.2.0)
develop       ← التكامل، محمي، PR فقط
feature/*     ← من develop، عمر قصير (< 3 أيام مثالي)
bugfix/*      ← من develop
hotfix/*      ← من main، يُدمج في main و develop
release/*     ← تحضير إصدار (تجميد الميزات)
```

**قواعد الحماية (Branch Protection على main/develop):**
- ✅ PR مطلوب (لا push مباشر).
- ✅ 2 approvals على الأقل (1 لكود حساس).
- ✅ كل الـ checks خضراء (CI).
- ✅ الفرع محدّث مع الهدف (no stale).
- ✅ squash merge لـ feature، merge commit لـ release.
- ✅ حذف الفرع بعد الدمج.

### 17.2 صيغة الـ Commit (Conventional + نطاق)

```
<type>(<scope>): <subject>

[body اختياري: لماذا، لا ماذا]

[footer: BREAKING CHANGE / Refs / Closes]
```

## 18. Code Review Guidelines

### 18.1 للمراجع (Reviewer)

```markdown
## الأولويات (بالترتيب)
1. **الصحة والأمان:** منطق صحيح؟ ثغرات؟ IDOR؟ injection؟ تسريب PII؟
2. **المعمارية:** يلتزم بـ 04؟ حدود الـ modules محترمة؟ لا اعتماد دائري؟
3. **المعايير:** يلتزم بهذا الملف؟ أسماء؟ أنماط؟
4. **الاختبارات:** كافية؟ تغطي الحواف؟ الحرجة؟
5. **الأداء:** N+1؟ cache؟ عمل ثقيل في المسار الحرج؟
6. **القراءة:** واضح؟ موثق؟ أبسط حل؟

## آداب المراجعة
- ✅ علّق على الكود لا الشخص.
- ✅ اشرح "لماذا"، واقترح حلاً، لا تكتفِ بـ "غيّر هذا".
- ✅ ميّز: `must` (إلزامي) / `should` (مهم) / `nit` (تفضيل) / `question`.
- ✅ امدح الحلول الجيدة صراحة.
- ✅ راجع خلال 24 ساعة عمل.
- ❌ لا تطلب تغييرات تفضيلية خارج المعايير (احترم الـ Prettier/ESLint).
```

### 18.2 للمؤلف (Author)

```markdown
- ✅ رد على كل تعليق (حلّ أو اشرح أو افتح نقاشاً).
- ✅ لا تدمج بدون approvals مكتملة.
- ✅ PR صغير ومركّز (< 400 سطر تغيير مثالي؛ قسّم الكبير).
- ✅ وصف واضح + سياق + لقطات للـ UI.
- ✅ self-review أولاً (اقرأ diff بنفسك).
```

## 19. Definition of Done (DoD)

> **لا تُعتبر المهمة منتهية، ولا تُدمج، ولا تُنشر، إلا بتحقيق كل البنود:**

```markdown
## Definition of Done — MOTANAQIL

### الكود
- [ ] يحقق المتطلب الموثّق (ربط بـ 26-Traceability-Matrix)
- [ ] يتبع 12-Coding-Standards و 05.05-Naming
- [ ] TypeScript strict، لا `any`، لا `console.log`
- [ ] معالجة أخطاء typed، رسائل آمنة بالعربية
- [ ] PII منقّية من الـ logs والاستجابات

### الجودة
- [ ] `npm run validate` أخضر (type + lint + format + test)
- [ ] Unit tests للمنطق (coverage ≥ 80% للملف، ≥ 90% للحرج)
- [ ] Integration tests للـ endpoints المتأثرة
- [ ] E2E للمسار الحرج إن تأثر (ملف 10)
- [ ] لا تحذيرات build

### الأمان
- [ ] لا ثغرات SAST/SCA جديدة (CI)
- [ ] validation على الحدود، parameterized queries

- [ ] JSDoc للـ public APIs

- [ ] CHANGELOG إن تغيير مرئي

### المراجعة والنشر
- [ ] Code review مكتمل (≥ 2 approvals للحساس)
- [ ] migrations متوافقة ومختبرة على staging
- [ ] لا تأثير رجعي (regression) على الميزات السابقة
- [ ] merged في develop، جاهز للإصدار حسب 13-Release-Management
```

## 20. Anti-Patterns (الممنوعات)

```typescript
// 🚫 قائمة الممنوعات الصريحة (تُراجع في كل PR)

// 1. ابتلاع الأخطاء
try { await risky(); } catch (e) {}                       // 🚫

// 2. any
const data: any = await fetch(...);                       // 🚫

// 3. منطق أعمال في controller
@Controller() class C { @Post() create() { /* حساب سعر */ } } // 🚫

// 4. prisma في service مباشرة
@Injectable() class S { constructor(private p: PrismaService){} } // 🚫 (عبر repo)

// 5. N+1
for (const o of orders) o.user = await findUser(o.userId); // 🚫

// 6. hardcoded strings للمستخدم
return <button>إرسال</button>;                            // 🚫 (i18n)

// 7. hardcoded secrets
const key = 'sk_live_abc123';                             // 🚫

// 8. magic numbers
if (status === 3) { ... }                                 // 🚫 (استخدم enum/const)

// 9. default export (عدا next pages)
export default class Foo {}                               // 🚫

// 10. index as key
list.map((x, i) => <Item key={i} />)                      // 🚫

// 11. useEffect بدون cleanup للم subscriptions/sockets
useEffect(() => { socket.on(...); }, []);                 // 🚫

// 12. await في حلقة بدون سبب
for (const id of ids) await fetch(id);                    // 🚫 (Promise.all/batch)

// 13. تعليق يكرر الكود / TODO بدون ticket
// 🚫

// 14. fetch بدون validation للنتيجة
const data = await res.json(); /* استخدام مباشر */        // 🚫 (schema.parse)

// 15. تعديل state مباشرة (React)
items.push(x); setItems(items);                           // 🚫 (setItems([...items, x]))
```

## 22. فرض المعايير آلياً (Enforcement)

### 22.1 طبقات الفرض

```
┌─────────────────────────────────────────────────────────┐
│ 1. المحرر (Editor)     — ESLint/Prettier on save       │
│ 2. pre-commit (husky)  — lint-staged على الملفات المعدلة│
│ 3. pre-push (husky)    — type-check + tests المتأثرة    │
│ 4. commit-msg          — commitlint                     │
│ 5. CI (PR)             — validate كامل + SAST + SCA     │
│ 6. Code Review         — ما لا يُفرض آلياً (منطق/تصميم) │
│ 7. Branch Protection   — لا دمج بدون كل ما سبق أخضر     │
└─────────────────────────────────────────────────────────┘
```

### 22.2 CI Gate (لا دمج بدونها)

```yaml
# جزء من .github/workflows/ci.yml
quality-gate:
  steps:
    - run: npm run type-check          # TypeScript strict
    - run: npm run lint                # ESLint --max-warnings 0
    - run: npm run format:check        # Prettier
    - run: npm run test -- --coverage  # مع عتبة تغطية
    - run: npx madge --circular apps/  # لا اعتماد دائري
    - run: npx depcruise --validate .dependency-cruiser.cjs apps/
    - uses: sonarsource/sonarcloud-github-action  # جودة + تعقيد
```
