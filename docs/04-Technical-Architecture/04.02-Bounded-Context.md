## 1. نظرة عامة

تقسيم النظام إلى سياقات محدودة (Bounded Contexts) حسب Domain-Driven Design.

---

## 2. السياقات المحددة

### 2.1 Customer Context (سياق العميل)

**المسؤولية:** إدارة تجربة العميل

**الكيانات:**
- Customer (User بـ role=customer)
- CustomerProfile
- CustomerAddress
- CustomerPreferences

**العمليات:**
- تسجيل حساب جديد
- تعديل الملف الشخصي
- إدارة العناوين
- عرض سجل الطلبات
- تقديم تقييم

**الـ APIs:**
- `POST /api/v1/auth/register`
- `PATCH /api/v1/customers/profile`
- `GET /api/v1/customers/orders`
- `POST /api/v1/customers/reviews`

**الحدود:**
- لا يتعامل مع إدارة الموظفين
- لا يعدل أسعار الخدمات
- لا يدير المحتوى

---

## 3. خريطة التواصل بين السياقات

```
┌─────────────────────────────────────────────────────────┐
│                    Event Bus (Redis)                     │
└─────────────────────────────────────────────────────────┘
         ↑              ↑              ↑              ↑
         │              │              │              │
    ┌────┴────┐    ┌────┴────┐    ┌────┴────┐    ┌────┴────┐
    │ Orders  │    │ Billing │    │  Fleet  │    │  CMS    │
    │ Context │    │ Context │    │ Context │    │ Context │
    └────┬────┘    └────┬────┘    └────┬────┘    └────┬────┘
         │              │              │              │
         └──────────────┴──────────────┴──────────────┘
                              ↓
                    ┌─────────────────┐
                    │  Notifications  │
                    │     Context     │
                    └─────────────────┘
```

**أحداث المجال:**
- `OrderCreated` → Billing (إنشاء فاتورة) + Notifications (إرسال تأكيد)
- `OrderAssigned` → Fleet (تحديث موقع السائق) + Notifications (إشعار الموظف)
- `OrderCompleted` → Billing (تحديث الفاتورة) + Notifications (طلب تقييم)
- `PaymentReceived` → Orders (تحديث حالة الدفع)

## 4. قواعد العزل

### 4.1 ممنوع
- ❌ استدعاء مباشر بين سياقات مختلفة
- ❌ مشاركة جداول قاعدة البيانات بين سياقات
- ❌ اعتماد سياق على تفاصيل تنفيذ سياق آخر

### 4.2 مسموح
- ✅ التواصل عبر Event Bus
- ✅ استخدام Anti-Corruption Layer للتكامل
- ✅ مشاركة Value Objects فقط
- ✅ استخدام Shared Kernel للكيانات الأساسية (User, Money)

---

## 5. Shared Kernel

**الكيانات المشتركة:**
- User (الهوية الأساسية)
- Money (القيمة النقدية)
- Coordinates (الإحداثيات)
- DateRange (الفترة الزمنية)

**القواعد:**
- لا تتغير إلا بموافقة جميع السياقات
- موثقة في Domain Model
- مستقرة عبر الإصدارات
