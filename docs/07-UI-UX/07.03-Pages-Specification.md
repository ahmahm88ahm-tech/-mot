## 1. نظرة عامة

### 1.1 فلسفة التصميم

جميع صفحات MOTANAQIL تتبع المبادئ التالية:

- **Mobile-First:** تصميم يبدأ من الجوال ثم يتوسع
- **RTL-Native:** دعم كامل للغة العربية من اليمين لليسار
- **Performance-First:** تحميل سريع (< 3 ثوانٍ)
- **SEO-Optimized:** تحسين كامل لمحركات البحث
- **Accessibility:** متوافق مع WCAG 2.1 AA
- **Consistent:** استخدام Design System موحد

### 1.2 التقنيات المستخدمة

```typescript
// Frontend Stack
Framework: Next.js 14+ (App Router)
Language: TypeScript
Styling: Tailwind CSS
Animations: Framer Motion
Forms: React Hook Form + Zod
State: Zustand
Icons: Lucide React
Maps: @react-google-maps/api
Charts: Recharts
```

### 1.3 هيكل الصفحة الموحد

كل صفحة في المشروع تتبع هذا الهيكل:

```typescript
// app/(section)/page-name/page.tsx

import { Header } from '@/components/layout/header';

  title: '...',
  description: '...',
  openGraph: { ... },
};

// 2. Page Component
export default function PageName() {
  return (
    <>
      <Header />
      <main>
        {/* Page Sections */}
      </main>
      <Footer />
      <FloatingButtons />
    </>
  );
}
```

## 2. معايير الصفحات

### 2.1 معايير الأداء (Performance Budget)

| المقياس | الهدف | الحد الأقصى |
|--------|------|-----------|
| **LCP** (Largest Contentful Paint) | < 2.5s | 3s |
| **FID** (First Input Delay) | < 100ms | 150ms |
| **CLS** (Cumulative Layout Shift) | < 0.1 | 0.25 |
| **TTFB** (Time to First Byte) | < 600ms | 800ms |
| **FCP** (First Contentful Paint) | < 1.8s | 2.5s |
| **Total Page Size** | < 2MB | 3MB |
| **Images** | WebP/AVIF | JPG/PNG fallback |

### 2.2 معايير SEO لكل صفحة

- ✅ عنوان فريد (Title Tag) - 50-60 حرف
- ✅ وصف فريد (Meta Description) - 150-160 حرف
- ✅ Open Graph Tags كاملة
- ✅ Twitter Card Tags
- ✅ Schema.org Markup
- ✅ Canonical URL
- ✅ Hierarchy صحيحة (H1, H2, H3)
- ✅ Alt Text للصور
- ✅ Internal Linking
- ✅ Breadcrumbs

### 2.3 معايير الأمان

- ✅ HTTPS فقط
- ✅ Content Security Policy

- ✅ CSRF Protection
- ✅ Rate Limiting

### 2.4 معايير الوصول (Accessibility)

- ✅ Semantic HTML

## 13. User Flows

### 13.1 Flow: طلب خدمة (Guest)

```
1. الزائر يدخل الصفحة الرئيسية
2. يضغط "اطلب الخدمة"
3. ينتقل لـ /request
4. يملأ النموذج (6 خطوات)
5. في الخطوة 5: يُطلب منه تسجيل الدخول أو الاستمرار كضيف
6. إذا ضيف: يدخل بياناته الأساسية
7. يؤكد الطلب
8. يرى صفحة تأكيد مع رقم الطلب
9. ينتقل لـ /track/[orderNumber]
10. يتتبع الطلب
```

### 13.2 Flow: طلب خدمة (Customer)

```
1. العميل مسجل دخول
2. يضغط "اطلب الخدمة"
3. يملأ النموذج (بياناته محملة تلقائياً)
4. يؤكد الطلب
5. يرى التأكيد
6. يتتبع الطلب من Dashboard
```

### 13.3 Flow: إدارة طلب (Admin)

```
1. المدير يدخل Dashboard
2. يرى الطلبات الجديدة
3. يضغط على طلب
4. يرى التفاصيل
5. يضغط "تعيين موظف"
6. يختار من الموظفين المقترحين
7. يؤكد التعيين
8. يتم إرسال إشعار للموظف والعميل
9. يتابع حالة الطلب
```

## 17. Security Considerations

### 17.1 Authentication Guards

```typescript
// Middleware
export function middleware(request) {
  const token = request.cookies.get('token');
  
  if (!token && request.nextUrl.pathname.startsWith('/customer')) {
    return NextResponse.redirect('/auth/login');
  }
  
  if (!token && request.nextUrl.pathname.startsWith('/admin')) {
    return NextResponse.redirect('/auth/login');
  }
}
```

```typescript
// Role-based access
export default function AdminPage() {
  const { user } = useAuth();

  return <AdminContent />;
}
```
