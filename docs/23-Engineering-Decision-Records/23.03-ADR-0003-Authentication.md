# ADR-0003: اختيار نظام المصادقة (JWT + Refresh Tokens)

**Status:** ✅ Accepted  
**Date:** 2026-07-23  
**Deciders:** فريق Buytuk (Tech Lead, Security Lead)  
**Consulted:** Backend Lead, DevOps Lead  
**Informed:** فريق التطوير

---

## Context

مشروع MOTANAQIL يحتاج نظام مصادقة يدعم:

- **مستخدمون متعددون** — Customers, Employees, Drivers, Admins, Managers
- **صلاحيات دقيقة** — RBAC + Ownership Checks (ملف 09.01)
- **جلسات متعددة** — Multi-device, Session Management
- **أمان عالي** — MFA, Brute Force Protection, Device Detection
- **Real-time** — WebSocket يحتاج مصادقة
- **Mobile-ready** — للتطبيقات المستقبلية

**المشكلة:** اختيار نظام مصادقة يوازن بين:
- الأمان (Security)
- تجربة المستخدم (UX)
- الأداء (Performance)
- قابلية التوسع (Scalability)

## Decision Drivers

1. ** Stateless** — لا Session Storage في الخادم (Scalability)
2. **Multi-device** — المستخدم قد يكون على جوال + كمبيوتر
3. **Real-time** — WebSocket يحتاج مصادقة سريعة
4. **MFA** — إلزامي للإدارة (ملف 09-Security)
5. **Mobile-ready** — للتطبيقات المستقبلية

## Considered Options

### Option 1: JWT + Refresh Tokens ✅

**الوصف:** Access Token قصير العمر (15 دقيقة) + Refresh Token طويل العمر (7 أيام) مع Rotation.

**المزايا:**
- ✅ **Stateless** — لا Session Storage، Scalability ممتاز
- ✅ **Multi-device** — كل جهاز له Refresh Token مستقل
- ✅ **Real-time** — WebSocket مصادقة سريعة (Token في Header)
- ✅ **MFA** — سهل التكامل (TOTP, SMS)
- ✅ **Mobile-ready** — Tokens تعمل في Mobile Apps
- ✅ **Rotation** — Refresh Token يتجدد مع كل استخدام (أمان عالي)
- ✅ **Revocation** — Blacklist للـ Tokens الملغاة

**العيوب:**
- ❌ **Token Size** — JWT أكبر من Session ID (لكن negligible)
-  **Complexity** — Rotation + Reuse Detection معقد (لكن Prisma + Redis يعوضان)

### Option 2: Session-based (Express-Session)

**الوصف:** Session ID في Cookie، Session Data في الخادم (Redis/DB).

**المزايا:**
- ✅ **بسيط** — سهل الفهم والتطبيق
- ✅ **Revocation سهل** — حذف Session من الخادم
- ✅ **Small Token** — Session ID صغير

**العيوب:**
- ❌ **Stateful** — Session Storage في الخادم (Scalability محدود)
- ❌ **Multi-device صعب** — Session واحد لكل مستخدم
- ❌ **WebSocket معقد** — يحتاج Session Lookup في كل رسالة
- ❌ **Mobile صعب** — Cookies غير مناسبة لـ Mobile Apps
- ❌ **MFA معقد** — يحتاج Session State Management

### Option 3: OAuth 2.0 + OpenID Connect

**الوصف:** بروتوكول مصادقة قياسي (Google, Facebook, etc.)

**المزايا:**
- ✅ **قياسي** — بروتوكول معتمد عالمياً
- ✅ **Social Login** — Google, Facebook, Apple
- ✅ **Third-party** — تكامل مع أنظمة خارجية

**العيوب:**
- ❌ **معقد** — بروتوكول معقد، يحتاج وقت طويل للتطبيق
-  **Overkill** — لا نحتاج Third-party Apps في المرحلة الأولى
- ❌ **تكلفة** — Identity Provider (Auth0, Okta) مكلف
- ❌ **Latency** — Redirects متعددة تبطئ UX

## Decision Outcome

**Chosen option:** Option 1 — JWT + Refresh Tokens

**السبب:**
1. **Stateless** — Scalability ممتاز، لا Session Storage
2. **Multi-device** — كل جهاز له Refresh Token مستقل
3. **Real-time** — WebSocket مصادقة سريعة (Token في Header)
4. **MFA** — سهل التكامل (TOTP, SMS)
5. **Mobile-ready** — Tokens تعمل في Mobile Apps
6. **Rotation** — أمان عالي (Refresh Token يتجدد مع كل استخدام)
7. **Cost** — مجاني (لا Identity Provider مكلف)

**البنية المختارة:**
```
Access Token: JWT (RS256, 15 دقيقة)
Refresh Token: Opaque (7 أيام, Rotation, Reuse Detection)
Storage: Access Token في Memory (Client), Refresh Token في HttpOnly Cookie
MFA: TOTP (Google Authenticator) + SMS (Unifonic)
Password Hashing: bcrypt (cost=12) أو argon2id
```

## Consequences

### إيجابية
- ✅ **Scalability** — Stateless، لا Session Storage
- ✅ **Multi-device** — كل جهاز له Refresh Token مستقل
- ✅ **Real-time** — WebSocket مصادقة سريعة
- ✅ **MFA** — سهل التكامل
- ✅ **Mobile-ready** — Tokens تعمل في Mobile Apps
- ✅ **أمان عالي** — Rotation + Reuse Detection

### سلبية
- ️ **Token Size** — JWT أكبر من Session ID (لكن negligible)
- ⚠️ **Complexity** — Rotation + Reuse Detection معقد (لكن Prisma + Redis يعوضان)

### مخاطر
- 🔴 **Risk:** Token Theft (XSS, MITM)  
  **Mitigation:** HttpOnly Cookies + CSP + TLS 1.3 + Short-lived Access Tokens
- 🔴 **Risk:** Refresh Token Reuse (سرقة)  
  **Mitigation:** Reuse Detection + Family Revocation (ملف 09-Security §6.2)

## Compliance

- ✅ **Security:** RS256 (غير متماثل) + Key Rotation كل 90 يوم
- ✅ **Storage:** Access Token في Memory، Refresh Token في HttpOnly Cookie
- ✅ **MFA:** إلزامي لـ Admin/Manager، موصى به للآخرين
- ✅ **Monitoring:** Login Attempts + Device Detection + Impossible Travel
