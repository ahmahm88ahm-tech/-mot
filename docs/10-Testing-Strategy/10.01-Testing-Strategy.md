## ⚠️ مبدأ حاكم

> **الاختبار ليس "البحث عن الأخطاء"، بل "إثبات الجودة".** كل خاصية تُكتب تُختبر تلقائياً. لا تُعتبر أي ميزة "مُسلَّمة" حتى تمرّ عبر جميع طبقات الاختبار (Unit → Integration → E2E → Load → Security → Accessibility). لا تُرفع أي تغيير إلى الإنتاج بدون تقرير اختبار مُحدّث، ولا تُسلّم أي إصدار دون تقرير اختبار كامل (`Testing-Report.pdf`). إذا لم تُختبر، فهي لا تعمل.

## 1. الرؤية والمبادئ

### 1.1 الرؤية

> **الاختبار جزء من التصميم، وليس خطوة لاحقة.** كل تغيير يُكتب يُختبر تلقائياً، ويُوثق تأثيره على تغطية الاختبارات. الهدف: **90%+ تغطية للمنطق الحرج، 100% تغطية للـ workflows الحرجة، 0 أخطاء حرج في الإنتاج.**

### 1.2 المبادئ الحاكمة

| المبدأ | التطبيق في MOTANAQIL |
|--------|---------------------|
| **Test-Driven Development (TDD)** | يُفضّل كتابة اختبارات قبل الكود للمنطق الحرج |
| **Shift-Left Testing** | الاختبارات تبدأ من أول تذكرة، لا من مرحلة الـ testing |
| **Test Pyramid** | 70% Unit, 20% Integration, 10% E2E |
| **Fail Fast** | كشف الأخطاء مبكراً، لا انتظار الـ E2E |
| **Automate Everything** | كل ما يُكرر يُختبر تلقائياً (لا اختبار يدوي) |
| **Reproducible Tests** | نفس الإدخال → نفس الخرج (لا عوامل خارجية) |
| **Test as a Contract** | كل اختبار يُوثّق عقدة (ما يجب أن يعمل) |
| **Test for Failure** | اختبار الفشل (لا النجاح فقط) |

## 2. البنية المعمارية للاختبارات

### 2.1 Test Pyramid

```
                      ┌─────────────────────────────┐
                      │   E2E Tests (10%)           │
                      │   • End-to-End workflows    │
                      │   • User journeys           │
                      │   • Cross-service scenarios │
                      └─────────────────────────────┘
                      ┌─────────────────────────────┐
                      │   Integration Tests (20%)   │
                      │   • Service boundaries      │
                      │   • API contracts           │
                      │   • DB interactions         │
                      └─────────────────────────────┘
                      ┌─────────────────────────────┐
                      │   Unit Tests (70%)          │
                      │   • Functions               │
                      │   • Classes                 │
                      │   • Pure utilities          │
                      └─────────────────────────────┘
```

### 2.2 مسارات الاختبار

```
┌─────────────────────────────────────────────────────────┐
│  1. تطوير الميزة (Feature)                          │
│  • كتابة اختبارات وحدة (TDD)                         │

                          ↓
┌─────────────────────────────────────────────────────────┐
│  2. مراجعة الكود (Code Review)                       │
│  • مراجعة اختبارات الوحدة والتكامل                   │
│  • التأكد من تغطية الاختبارات                       │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  3. مراجعة الميزات (Feature Review)                  │

                          ↓

                          ↓
┌─────────────────────────────────────────────────────────┐
```

## 3. اختبارات الوحدة (Unit Testing)

### 3.1 الاستراتيجية

```typescript
const unitTestingStrategy = {
  coverage: {
    global: { lines: 80, branches: 70, functions: 80, statements: 80 },
    critical_modules: { lines: 90, branches: 85 }, // orders, auth, pricing, security
    ignore: ['DTOs', 'types', 'mappers', 'config'],
  },
  scope: [
    'المنطق الحرج (الحسابات، التشفير، التحقق)',
    'المستويات المهمة (API, Services)',
    'الوظائف pure (لا side effects)',
  ],
  tools: [
    'Jest', 'Vitest', 'Jasmine', 'Mocha',
    'Testcontainers (للاختبارات مع DB)',
    'MSW (لـ API mocking)',
  ],
  patterns: [
    'الاختبارات تبدأ بـ `test(‘...’, () => { ... })`',
    'لا تكرار الم setUp/tearDown (استخدم `beforeEach`)',
    'اختبارات قصيرة ومحددة (1-2 أشياء في كل اختبار)',
    'استخدم `describe` لتنظيم المجموعات',
    'استخدم `it` لوصف السيناريو (ما يفعله، لا كيف)',
  ],
};
```

### 3.2 أمثلة كود

```typescript
// tests/orders/order-price-calculator.spec.ts
import { OrderPriceCalculator } from '@/modules/orders/order-price-calculator';
import { OrderStatus } from '@motanaqil/types';

describe('OrderPriceCalculator', () => {
  const calculator = new OrderPriceCalculator();

  describe('calculate()', () => {
    it('يحسب السعر الإجمالي مع الضريبة', () => {
      const input = {
        basePrice: 500,
        extraServices: [{ name: 'تغليف', price: 100 }],
        taxRate: 0.15,
      };
      
      const result = calculator.calculate(input);
      
      expect(result.totalAmount).toBe(690); // 500 + 100 + (500+100)*0.15
    });

    it('يُعيد خطأ عند خروج السعر من الحدود', () => {
      const input = {
        basePrice: 100000,
        extraServices: [],
        taxRate: 0.15,
      };
      
      expect(() => calculator.calculate(input)).toThrow(ValidationError);
    });
  });

  describe('validate()', () => {
    it('يتحقق من صحة المدخلات', () => {
      expect(calculator.validate({ basePrice: 500 })).toBe(true);
      expect(calculator.validate({ basePrice: -100 })).toBe(false);
    });
  });
});
```

### 3.3 معايير القبول

```typescript
const unitTestAcceptance = {
  must_pass: [
    'كل اختبار وحدة يمرّ (لا فشل)',
    'تغطية ≥ 80% للملف (90% للحرج)',
    'لا تكرار مفرط (لا multiple asserts في اختبار واحد)',
    'لا تكرار في الإعداد (لا repetitive setup)',
    'تغطية كل السيناريوهات (مهمة، ناجحة، فاشلة)',
    'لا تعتمد على الوقت (Date.now() → mocked)',
    'لا تعتمد على الشبكة (APIs → mocked)',
  ],
  must_fail: [
    'اختبارات وحدة تُفشل عند تغيير سلوك المكون',
    'اختبارات تُظهر كود غير مُختبر (uncovered lines)',
    'اختبارات تُظهر ثغرات (مثل خروج عن الحدود)',
  ],
};
```

### 4.2 أمثلة كود

```typescript
// tests/orders/orders.service.integration.spec.ts
import { Test, TestingModule } from '@nestjs/testing';
import { OrdersService } from '@/modules/orders/orders.service';
import { PrismaService } from '@/prisma/prisma.service';
import { OrderStatus } from '@motanaqil/types';

describe('OrdersService (Integration)', () => {
  let service: OrdersService;
  let prisma: PrismaService;

  beforeEach(async () => {
    const module: TestingModule = await Test.createTestingModule({
      providers: [OrdersService, PrismaService],
    }).compile();

    service = module.get<OrdersService>(OrdersService);
    prisma = module.get<PrismaService>(PrismaService);
    
    // مسح البيانات قبل كل اختبار
    await prisma.order.deleteMany();
  });

  it('يخلق طلباً جديداً', async () => {
    const input = { serviceId: '1', fromAddress: { /* ... */ } };
    const order = await service.create(input);
    
    expect(order).toHaveProperty('id');
    expect(order.status).toBe(OrderStatus.CREATED);
    
    // تحقق من قاعدة البيانات
    const dbOrder = await prisma.order.findUnique({ where: { id: order.id } });
    expect(dbOrder).toBeTruthy();
  });

  it('يرفض طلباً مع عنوان غير صالح', async () => {
    const input = { serviceId: '1', fromAddress: { address: '123' } };
    await expect(service.create(input)).rejects.toThrow(ValidationError);
    
    // تحقق من أن الطلب لم يُنشأ
    expect(await prisma.order.count()).toBe(0);
  });
});
```
