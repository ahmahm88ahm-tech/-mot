# ADR-0004: اختيار نظام الإشعارات (Event-Driven + Multi-Channel)

**Status:** ✅ Accepted  
**Date:** 2026-07-24  
**Deciders:** فريق Buytuk (Tech Lead, Backend Lead)  
**Consulted:** Product Owner, DevOps Lead  
**Informed:** فريق التطوير

---

## Context

مشروع MOTANAQIL يحتاج نظام إشعارات يدعم:

- **قنوات متعددة** — Email, SMS, WhatsApp, Push, In-App
- **أحداث كثيرة** — 40+ حدث (ملف 19-Notifications)
- **موثوقية عالية** — لا إشعار مفقود
- **تتبع التسليم** — Delivery Tracking
- **تفضيلات المستخدم** — Opt-in/Opt-out لكل قناة
- **Rate Limiting** — منع الإزعاج (Anti-Spam)

**المشكلة:** اختيار بنية إشعارات توازن بين:
- الموثوقية (Reliability)
- الأداء (Performance)
- المرونة (Flexibility)
- التكلفة (Cost)

## Decision Drivers

1. **موثوقية** — لا إشعار مفقود (Retry + Dead Letter Queue)
2. **أداء** — لا إبطاء التطبيق الرئيسي (Async Processing)
3. **مرونة** — إضافة قنوات جديدة بسهولة
4. **تتبع** — Delivery Tracking لكل إشعار
5. **تفضيلات** — Opt-in/Opt-out لكل مستخدم

## Considered Options

### Option 1: Event-Driven + BullMQ + Multi-Provider ✅

**الوصف:** أحداث تُنشر عبر Event Bus، تُعالج في طوابير (BullMQ)، تُرسل عبر مزودين متعددين مع Failover.

**المزايا:**
- ✅ **موثوقية** — Retry + Dead Letter Queue + Failover
- ✅ **أداء** — Async Processing، لا إبطاء التطبيق
- ✅ **مرونة** — إضافة قنوات/مزودين بسهولة (Strategy Pattern)
- ✅ **تتبع** — Delivery Tracking لكل إشعار
- ✅ **تفضيلات** — Opt-in/Opt-out لكل مستخدم
- ✅ **Rate Limiting** — منع الإزعاج
- ✅ **قوالب** — Template Engine (Handlebars) + i18n

**العيوب:**
- ❌ **تعقيد** — Event Bus + Queues + Multi-Provider معقد
- ❌ **تكلفة** — مزودين متعددين (SendGrid, Unifonic, Meta)

### Option 2: Direct Integration (No Queue)

**الوصف:** إرسال مباشر من التطبيق إلى المزودين (No Queue).

**المزايا:**
- ✅ **بسيط** — سهل الفهم والتطبيق
- ✅ **سريع** — لا Queue Latency

**العيوب:**
- ❌ **موثوقية ضعيفة** — فشل المزود = إشعار مفقود
- ❌ **أداء** — إبطاء التطبيق (Sync Processing)
-  **لا Retry** — لا إعادة محاولة
- ❌ **لا Tracking** — لا Delivery Tracking
- ❌ **لا Flexibility** — صعب إضافة قنوات/مزودين

### Option 3: Third-party Service (OneSignal, Firebase)

**الوصف:** خدمة خارجية تدير الإشعارات.

**المزايا:**
- ✅ **بسيط** — لا بنية تحتية
- ✅ **موثوق** — خدمة مُدارة
- ✅ **تتبع** — Delivery Tracking مدمج

**العيوب:**
- ❌ **تكلفة** — مكلف عند النمو (10,000+ مستخدم)
- ❌ **Vendor Lock-in** — مرتبط بمزود واحد
- ❌ **مرونة محدودة** — لا تحكم كامل في القوالب/القنوات
- ❌ **Latency** — اعتماد على خدمة خارجية

## Decision Outcome

**Chosen option:** Option 1 — Event-Driven + BullMQ + Multi-Provider

**السبب:**
1. **موثوقية** — Retry + Dead Letter Queue + Failover
2. **أداء** — Async Processing، لا إبطاء التطبيق
3. **مرونة** — إضافة قنوات/مزودين بسهولة (Strategy Pattern)
4. **تتبع** — Delivery Tracking لكل إشعار
5. **تفضيلات** — Opt-in/Opt-out لكل مستخدم
6. **Rate Limiting** — منع الإزعاج
7. **قوالب** — Template Engine (Handlebars) + i18n

**البنية المختارة:**
```
Event Bus: EventEmitter2 (NestJS)
Queue: BullMQ (Redis)
Providers:
  - Email: SendGrid (Primary) + AWS SES (Fallback)
  - SMS: Unifonic (Primary) + Twilio (Fallback)
  - WhatsApp: Meta API (via Twilio/360dialog)
  - Push: FCM (Mobile) + VAPID (Web)
  - In-App: WebSocket (Socket.io)
Template Engine: Handlebars + i18n
Tracking: Delivery Logs (PostgreSQL)
```

## Consequences

### إيجابية
- ✅ **موثوقية عالية** — Retry + Failover + Dead Letter Queue
- ✅ **أداء ممتاز** — Async Processing، لا إبطاء التطبيق
- ✅ **مرونة** — إضافة قنوات/مزودين بسهولة
- ✅ **تتبع كامل** — Delivery Tracking لكل إشعار
- ✅ **تفضيلات** — Opt-in/Opt-out لكل مستخدم
- ✅ **Rate Limiting** — منع الإزعاج

### سلبية
- ⚠️ **تعقيد** — Event Bus + Queues + Multi-Provider معقد
- ⚠️ **تكلفة** — مزودين متعددين (SendGrid, Unifonic, Meta)

### مخاطر
- 🔴 **Risk:** Queue Failure (Redis Down)  
  **Mitigation:** Redis Cluster + Monitoring + Alerting
-  **Risk:** Provider Failure (SendGrid Down)  
  **Mitigation:** Failover to AWS SES + Retry + Alerting

## Compliance

- ✅ **Reliability:** Retry (5 attempts, Exponential Backoff) + Dead Letter Queue
- ✅ **Performance:** Async Processing + Queue Priorities
- ✅ **Flexibility:** Strategy Pattern for Providers
- ✅ **Tracking:** Delivery Logs for every notification
- ✅ **Preferences:** Opt-in/Opt-out per user per channel
- ✅ **Rate Limiting:** Anti-Spam Rules
